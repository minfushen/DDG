# 产品规范（Specification）

> WHAT 与 WHY — 用业务语言描述系统该具备什么能力、为什么。
> 任何 plan.md / tasks.md 中的工作都必须能在本文找到对应的"用例编号"。

---

## 1. 产品目标

### 1.1 一句话目标

让银行客户经理在**单一工作台**完成"贷前 → 贷中 → 贷后 → 运营"全链路尽调作业，**AI 替代 70% 重复劳动**，人工只做高价值判断与决策。

### 1.2 北极星指标

| 指标 | 当前值（Demo） | 目标 | 备注 |
|------|----------------|------|------|
| 单笔尽调耗时 | 3 天（行业基线） | ≤ 6 小时 | 来自首页"平均节省时长" |
| 报告自动化率 | 82.5%（Demo） | ≥ 80% 持续保持 | AI 生成页数 / 总页数 |
| 数据引擎健康度 | 80%（4/5 数据源） | ≥ 95% | 已连接数据源 / 总数 |
| 风险预警响应时长 | — | ≤ 1 小时 | 触发到任务进入工作台 |

> 上述指标的语义详见 `docs/BUSINESS-DESIGN.md` 第二章。

## 2. 用户旅程（核心三人称）

### 2.1 P1 - 客户经理（张经理）日常

```
07:00 通勤路上     →  打开手机端浏览今日待办
09:00 到岗         →  电脑打开 / → 看任务分发台 → 锁定 1-3 件高优先事项
09:30 处理预警     →  /post-loan/dashboard → 风险追踪 → 联系客户
11:00 录入新尽调   →  /data-integration/{id} → 上传材料 / 触发数据采集
14:00 复核报告     →  /report/{id} → 编辑/微调 → 提交审批
16:30 答审批问询   →  /approval/risk-chat → AI 辅助回应
17:30 收尾归档     →  /post-loan/check → 更新检查记录
```

### 2.2 P2 - 审批人

```
打开 /approval/dashboard → 选任务 → 看摘要 → 看证据（合同对比 / 资金流向 / 风险问答）
                                                              ↓
                                                        通过 / 退回 / 驳回
```

### 2.3 P3 - 部门主管

```
打开 /analytics → 看团队效率、自动化率、风险分布 → 输出周报
```

## 3. 模块规范（按业务域划分）

> 编号规则：`SPEC-<模块代号>-<序号>`，PR 与 tasks 引用此编号。

### 3.1 SPEC-DASH 工作台首页

**业务定位**：任务分发台（**不是**数据总览台）。

| 编号 | 用例 | 验收标准 |
|------|------|---------|
| SPEC-DASH-1 | 用户登录后默认进入工作台 | `/` 渲染 Dashboard，3 秒内可见任务列表 |
| SPEC-DASH-2 | 任务按紧急度排序 | 顺序：贷后预警 > 即将到期年审 > 进行中 > 待开始 > 已完成（默认折叠） |
| SPEC-DASH-3 | 每条任务展示企业名 + 状态 + 风险等级 + 主操作按钮 | 主操作按状态变化（gathering 显示"查看进度"，report_ready 显示"复核报告"） |
| SPEC-DASH-4 | AI 一句话摘要 | 顶部显示"今日 N 个任务待处理，其中 M 个高优先级" |
| SPEC-DASH-5 | 快捷入口 | [新建任务] [运营分析] [数据引擎状态] |

**不在范围**：首页不放 4 个 KPI 卡片（移到 `/analytics`）；不放数据源详情。

### 3.2 SPEC-DD 贷前尽调

| 编号 | 用例 | 关联状态机 |
|------|------|-----------|
| SPEC-DD-1 | 数据整合：上传材料 + 触发数据源采集 | `gathering` |
| SPEC-DD-2 | 智能分析：财务/经营/行业/司法多维评分 + 关系图谱 + 风险摘要（**专业深度对齐信贷/风控标尺**，见 `docs/product/22-prd-v2-professional-depth.md`） | `analyzing` |
| SPEC-DD-3 | 报告生成：富文本编辑 + AI 重写 + 章节模板 + 导出 | `report_ready` |
| SPEC-DD-4 | 智能体配置：可视化配置数据源、采集策略、评分模型 | 跨模块 |
| SPEC-DD-5 | 财务分析专业组件：偿债/盈利/营运/现金流四维分析 + **真实行业中位数对标 + 趋势归因 + 盈利质量 + 现金流质量 + 财务异常信号**（替换硬编码假基准） | `analyzing` |
| SPEC-DD-6 | 报告完成度仪表盘：实时显示各章节完成状态 + 智能填充建议 | `report_ready` |
| SPEC-DD-7 | 解析可信化：非上市公司扫描件 PDF 路由至 `FinancialPdfPipeline`，字段级 bbox 溯源，解析质量信号（红/黄/绿、是否需人工复核）下传分析与报告 | `gathering` |
| SPEC-DD-8 | 行业分析专业组件：细分行业定位防错分 + **落到企业授信传导 + 竞品市占率对标** + 周期/政策/上下游议价 | `analyzing` |

**业务规则**：

- 数据引擎健康度 < 60% 时，必须在分析报告顶部展示"数据不完整"标签
- 风险等级在 analyzing 阶段由 AI 评定，report_ready 允许人工调整（须留理由）
- 报告未保存离开页面必须二次确认
- 财务分析必须包含四维指标（偿债/盈利/营运/现金流），每项指标显示趋势、**真实行业中位数对比（来源可查，禁止硬编码假值）**
- 报告整体完成度 < 80% 时禁止提交审批
- 行业对标数据偏离行业中位数 > 20% 时高亮提示
- **【v2.0 专业深度硬条件】** 财务章节须含：趋势归因叙述（异常信号"现象—归因—风险定性—核查要点"）、盈利质量（扣非 vs 归母、政府补助依赖）、现金流质量（经营现金流/净利润、自由现金流）、财务异常信号识别；禁止出现"暂不可计算""行业平均 35%"等占位/假值表达（违反 `rubric` 语言红线记 P1）
- **【v2.0 专业深度硬条件】** 行业章节须：细分行业定位准确（10 家上市公司回归样例 0 错分）、落到本企业授信影响与关注点、含竞品市占率/排名对标、覆盖周期/政策/上下游议价；结论绑定 evidence
- **【v2.0 专业深度硬条件】** 解析可信：非上市公司上传 PDF 须路由至 `FinancialPdfPipeline`；报告中每个财务数字带可信度标记（红/黄/绿）并可点击溯源至原 PDF 坐标（bbox）；解析"需人工复核"触发 HITL 恢复（只记事务不改原文）
- **【v2.0 专业深度硬条件】** 报告须稳定输出 8 章结构（交叉验证与重大风险、信贷方案建议为独立一等公民章节），与 `rubric` 8 章验收一致

## 4. 跨模块共享规范

### 4.1 任务状态机（权威源）

> 详见 [`../BUSINESS-DESIGN.md`](../BUSINESS-DESIGN.md) 第一章。本文不重复，仅强制：

```
created → gathering → analyzing → report_ready → under_review → approved
                                                              ↘  rejected
                                                              ↘  archived
```

**不允许**：在 spec / plan / 代码中出现这 8 个之外的状态值。

### 4.2 风险等级（权威源）

`low | medium | high | critical` —— 全站统一，色值统一（见 `src/theme/tokens.ts` 的 `severity`）。

### 4.3 智能体协议

- **AG-UI**（Agent-User Interaction）：智能体输出事件流到 UI（文本增量、状态、工具调用、UI 渲染）
- **A2UI**（Agent-to-UI Schema）：服务端推动态 UI 描述给前端

详细 schema 见 `src/protocol/`，本规范只声明**所有"会跟用户对话"的页面（如 RiskChat）必须经过 AG-UI 协议**，不允许各自实现。

## 5. 非功能性规范

| 维度 | 规范 |
|------|------|
| 性能 | 首屏可交互 ≤ 1.5 秒（本地 dev）；任意路由切换 ≤ 300ms |
| 兼容性 | Chrome / Edge 最近 2 版；不支持 IE / 旧 Safari |
| 响应式 | 必须支持 1280 / 1440 / 1920 三个断点；移动端可读但不优先优化 |
| 可访问性 | 所有可点击元素有 hover / focus；表单元素有 label；色彩对比度 WCAG AA |
| 国际化 | 仅中文（简体）。i18n 框架不在当前范围 |
| 安全 | 当前无后端，无认证。接真后端时纳入 plan.md ADR |
