# 09 Sequential Thinking 金融尽调 DeepResearch Engine 产品设计

## 背景

当前 DDG-Agent MVP 已经具备“企业输入 - 四个专项 Agent - 完整尽调报告”的基础链路，但本质仍是固定流程编排：工商、财务、司法、行业顺序执行，然后合成报告。

参考 DeepResearch / Harness 工程思想后，下一阶段应将系统从“固定多 Agent 工作台”升级为“金融尽调研究引擎”。核心变化是：系统不再只是调用四个 Agent，而是先规划研究问题，再围绕证据需求调用工具、收集证据、形成可审计结论，最后输出 claim-evidence 报告。

## 产品定位

Sequential Thinking 金融尽调 DeepResearch Engine 是一个面向银行贷前尽调场景的研究型 Agent 引擎。

它的产品目标是：

- 将客户经理的尽调问题拆解为结构化研究任务。
- 将每个研究任务映射为证据需求。
- 通过工商、司法、财务、行业、RAG、公开搜索、用户上传材料等工具收集证据。
- 将证据转化为可追踪 Claim。
- 对 Claim 进行置信度、证据缺口和人工复核标记。
- 最终生成可审计的尽调报告，而不是一次性生成不可追踪文本。

## 核心体验变化

### 当前 MVP

```text
输入企业名
-> 判断任务类型
-> 调用工商/财务/司法/行业 Agent
-> 拼接完整报告
```

### DeepResearch Engine

```text
输入尽调目标
-> 生成研究计划
-> 拆解研究问题
-> 定义证据需求
-> 调用感知工具和专业 Agent
-> 归集 Evidence
-> 生成 Claim
-> 识别证据缺口
-> 补充检索或请求上传
-> 合成报告
```

## 目标用户价值

| 用户 | 价值 |
| --- | --- |
| 客户经理 | 不只是拿到报告，还能看到系统为什么查这些资料、哪些证据支撑结论、还缺什么材料 |
| 授信审查员 | 可追溯每条结论的证据来源和置信度，降低 AI 报告不可审计风险 |
| 风控/产品团队 | 将尽调经验沉淀为研究任务模板、证据规则和知识库资产 |
| 私有化客户 | 可将自购工商、司法、行政处罚等数据源接入研究引擎，替换公网搜索 |

## 核心产品对象

### Research Plan

研究计划，描述本次尽调需要回答哪些问题。

示例：

```json
{
  "objective": "对士兰微进行完整贷前尽调",
  "tasks": [
    "确认上市主体与证券代码是否匹配",
    "核查主营业务与行业分类是否一致",
    "分析近三年财务趋势和偿债能力",
    "检索司法、行政处罚、担保质押和重大公告风险",
    "判断行业周期和竞争格局对授信安全边界的影响"
  ]
}
```

### Research Task

单个研究问题，带有目的、证据需求、优先级和状态。

### Evidence Requirement

证据需求，例如：

- 上市公司基础信息。
- 近三年三大表。
- 主营构成。
- 诉讼公告。
- 行政处罚记录。
- 行业研报。
- 内部授信制度。

### Evidence

证据项，复用现有 Evidence Store，并增强 source_type、trust_level、requires_manual_review。

### Claim

研究结论声明，每条 Claim 必须绑定 evidence_ids。

例如：

```json
{
  "claim": "士兰微主营业务与集成电路制造行业分类基本一致",
  "evidence_ids": ["ev_xxx", "ev_yyy"],
  "confidence": 0.82,
  "missing_evidence": ["需补充主营构成按产品收入占比"],
  "risk_level": "medium"
}
```

### Research Gap

证据缺口，描述当前无法形成高置信结论的原因。

例如：

- 未获取正式审计报告。
- 行业研报来源可信度不足。
- 司法搜索仅命中新闻转载，未命中法院/执行公开源。
- 工商信息来自商业平台摘要，需权威工商接口复核。

## 页面展示建议

执行页应从普通时间轴升级为研究过程视图：

- 研究计划。
- 当前研究问题。
- 正在调用的工具。
- 已获得证据。
- 生成的 Claim。
- 证据缺口。
- 待用户上传材料。

报告页应新增：

- Claim-Evidence 表。
- 缺口与人工复核清单。
- 数据源可信度分布。
- 高成本权威数据源调用记录。

## 与 Sequential Thinking 的关系

Sequential Thinking 不用于展示模型私密思维链，而是用于产品化的研究步骤管理：

- 当前研究目标。
- 已完成步骤。
- 下一步证据需求。
- 是否需要补充检索。
- 是否可以生成结论。

前端展示的是“可审计研究步骤”，不是模型原始 chain-of-thought。

## MVP 范围

第一阶段只做最小研究引擎闭环：

1. 输入企业名和任务目标。
2. 生成默认研究计划。
3. 将现有四个单 Agent 和 RAG/Bocha 搜索作为工具。
4. 将工具结果归一化为 Evidence。
5. 根据 evidence 生成基础 Claim。
6. 输出 research_report JSON。

第一阶段不强求：

- 复杂多轮自我反思。
- 完整 Dify 迁移。
- 生产级多租户成本计费。
- 所有权威数据源接入。
