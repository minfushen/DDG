# 01 产品设计总览

## 产品定位

DDG-Agent 是一个面向银行客户经理和授信审查人员的智能尽调工作台。它的目标不是简单生成一段“企业风险分析”文本，而是将贷前尽调拆成多个专业专项：工商、财务、司法、行业，再由完整尽调流程合成一份可用于客户经理初筛、访谈准备和授信审查的结构化报告。

产品核心价值：

- 降低客户经理搜集资料、整理报告和初步识别风险的时间成本。
- 让 Agent 的执行过程可见，避免“点一下直接出报告”的黑盒感。
- 对缺失数据保持诚实，不静默编造财务指标。
- 通过 RAG、Evidence Store、质量闸门，把 LLM 从“语言润色器”升级为可追踪的尽调助手。

## 目标用户

| 用户 | 关注点 | 系统应提供的能力 |
| --- | --- | --- |
| 客户经理 | 快速判断企业是否值得进一步尽调 | 输入企业名即可生成初步尽调报告、待补充材料清单、风险访谈问题 |
| 授信审查人员 | 风险结论是否有证据支撑 | 报告展示证据来源、置信度、数据边界、人工复核事项 |
| 产品/风控团队 | 规则和知识能否持续沉淀 | 行业/财务/司法/工商知识库可迭代，触发规则可追踪 |
| 技术团队 | 链路是否稳定、可扩展 | 单 Agent 可独立测试，完整尽调可组合，外部工具可替换 |

## 核心用户流程

### 1. 首页输入

用户在首页输入自然语言，例如：

- `分析一下士兰微这个上市公司`
- `分析一下深圳市欣旺达能源科技有限公司的财务风险情况`
- `湖南省第二工程有限公司完整尽调`

系统做两件事：

1. 快速抽取企业名称和任务类型。
2. 创建任务并立即进入执行工作台。

设计调整记录：

- 早期创建任务时依赖 LLM 做意图识别，导致首页长时间转圈。
- 后来改为 `fast_extract_user_intent()` 本地快速解析，创建接口先返回任务 ID，后台再启动 Agent。
- 前端增加创建失败提示，避免后端异常时界面表现为“无限转圈”。

### 2. 执行工作台

执行页展示 Agent 过程，而不是直接跳转报告。当前设计重点：

- 顶部展示企业名称、任务状态、查看报告按钮。
- 左侧展示时间轴，包含系统、规划、工商、财务、司法、行业等节点。
- 右侧展示关键发现、证据计数、阶段性状态。
- 财务上传等待、LLM 生成、RAG 命中、公开搜索失败等状态均应可见。

该设计回应了测试中的反馈：

- “别啪一下跳到执行页，需要展示判断上市公司/非上市公司的思考过程。”
- “财务分析过程也需要展示思维链内容。”

这里的“思维链”在产品上被实现为可解释执行步骤，不展示模型内部不可控 chain-of-thought，而展示系统可审计的操作过程。

### 3. 报告结果页

报告页目标是接近客户经理可阅读的贷前尽调报告，而不是技术 JSON 展示。当前报告分为：

- 报告导言与核心概要。
- 企业基本情况与治理结构。
- 行业环境与经营分析。
- 财务状况与偿债能力。
- 司法与合规风险。
- 重大风险识别与交叉验证。
- 调查结论与信贷建议。
- 贷后管理要求。
- 数据来源、证据与待补充材料。

报告页需要明确展示：

- `公开资料预尽调` 或 `财报增强尽调`。
- 财务文本是 `LLM生成` 还是 `兜底模板`。
- 行业诊断是 `LLM生成` 还是 `兜底模板`。
- 数据边界、不可计算指标和待补充材料。
- Evidence Store 中的证据来源、置信度和复核状态。

## 双模式尽调

系统引入两种报告模式。

### 公开资料预尽调

适用场景：

- 非上市中小企业。
- 用户尚未上传近三年财报。
- 公开渠道能获取工商、司法、行业、经营线索，但核心财务数据不足。

设计原则：

- 不阻塞完整尽调。
- 不计算毛利率、净利率、资产负债率、现金流覆盖等缺失指标。
- 报告中明确披露“数据边界”和“待补充材料清单”。
- 输出初步准入建议、访谈问题和材料清单，而不是正式额度审批意见。

### 财报增强尽调

适用场景：

- 上市公司，可从公开渠道获取近三年财务数据。
- 非上市公司已上传近三年三大表。

设计原则：

- 财务核心指标必须来自结构化表格或公开财报。
- LLM 只负责诊断性表达，不负责凭空生成指标。
- 报告需能展示近三年趋势，而非只点评最新一年。
- 财务结论必须绑定数据边界和人工核查动作。

## 前端视觉设计原则

前端经历过多轮调整，目前形成三个页面风格：

1. 首页：ChatGPT 式入口，强调输入行为，避免营销页感。
2. 执行页：Manus 式时间轴，强调过程透明。
3. 报告页：DeepResearch 式结果页，强调可阅读、可审查、可追踪。

关键设计决策：

- 首页保持白底、单一视觉焦点，搜索框作为核心 CTA。
- 执行页不使用过多装饰卡片，突出时间轴和关键发现。
- 报告页按客户经理阅读顺序组织，而不是按后端字段机械展示。
- 使用橙色作为品牌强调色，保持与原型设计规范一致。

## 产品体验中的关键边界

产品不应伪装成“全自动审批系统”。报告必须持续提醒：

- 公开资料只能用于初筛。
- 外部搜索结果需要人工核验。
- 缺失财报时不能输出正式财务结论。
- LLM 生成文本需要质量闸门和证据追踪。
