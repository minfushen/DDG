# 14 竞品启发下的 DDG-Agent 产品改造任务清单

本文基于竞品分析结论整理，用于把 DDG-Agent 从“能跑通的智能尽调 MVP”推进到“客户经理能读、能复核、能交付的贷前尽调工作台”。

参考竞品类型包括：通用 DeepResearch/Manus 类研究 Agent、企业信息/风控平台、投研情报平台、法律/交易尽调 AI、交易资料室与尽调协同平台。

## 一、产品改造总目标

目标不是把 DDG-Agent 做成另一个企业信息查询工具，而是形成银行贷前尽调场景的差异化能力：

> 面向银行客户经理的金融尽调研究工作台，将公开资料、客户上传材料、内部授信知识库和大模型诊断能力整合成可审计的贷前尽调报告。

核心体验应满足：

- 执行页像 DeepResearch/Manus：能看到计划、工具调用、二轮补证和人工确认。
- 报告页像客户经理正式底稿：先给授信结论，再给专项分析、证据引用、数据边界和待补充材料。
- 每个关键结论都能回答“这句话由哪些证据支撑”。
- 不用 mock 数据填充正式结论，证据不足时必须明确边界和待补充材料。

## 二、目标报告信息架构

以下结构作为后续报告页、后端 `report_chapters`、DOCX/PDF 导出的共同目标结构。每个章节都应优先服务客户经理阅读，而不是展示 Agent 过程。

### 一、报告摘要与授信建议

- 综合评级
- 准入建议
- 核心风险
- 授信边界
- 数据边界

### 二、企业主体与治理结构

- 工商登记信息
- 股权结构与实控人
- 关联企业与对外投资
- 异常经营/行政处罚
- 正文级证据引用

### 三、财务状况与偿债能力

- 近三年收入、利润、现金流、资产负债
- 盈利质量
- 营运效率
- 偿债能力
- 财务异常信号
- 正文级证据引用

### 四、行业与经营环境

- 行业定位
- 周期判断
- 竞争格局
- 政策环境
- 上下游议价能力
- 授信关注点
- 正文级证据引用

### 五、司法与合规风险

- 裁判文书
- 被执行/失信
- 行政处罚
- 监管问询/公告
- 重大舆情
- 正文级证据引用

### 六、交叉验证与重大风险

- 财务与经营范围是否匹配
- 现金流与利润是否匹配
- 司法风险是否影响授信安全边界
- 行业周期是否影响还款来源

### 七、信贷方案建议

- 准入/审慎/暂缓
- 额度建议
- 期限建议
- 担保建议
- 提款前置条件
- 贷后监控指标

### 八、证据链与待补充材料

- Evidence 列表
- 证据缺口
- 待客户补充材料
- 人工复核事项

## 三、Outcome Roadmap

### Outcome 1：让客户经理一眼读懂授信结论

Outcome statement：Enable 客户经理 to 在 3 分钟内理解目标企业是否建议准入、主要风险和授信边界 so that 尽调报告能进入真实贷前初审讨论。

#### Initiative 1.1 报告页改成贷前尽调主线

- 优先级：P0
- 当前问题：报告页仍有研究过程感，部分章节像 DeepResearch 摘要，而不是贷前尽调报告。
- 改造内容：
  - 首页报告结构固定为：核心概要、四维评分、主体治理、财务、行业、司法、交叉验证、信贷建议、证据与待补充材料。
  - 执行过程、Research Plan、工具调用日志放入附录或执行页，不作为报告主线。
  - 报告第一屏只展示综合评级、准入建议、核心风险、数据边界。
- 验收标准：
  - 打开报告页 10 秒内可看到准入意见、风险评分和核心风险。
  - 报告主章节不出现“研究摘要”“工具过程结果”这类过程化标题。
  - 章节顺序符合客户经理阅读习惯。
- 依赖：当前 `report_chapters` 数据结构。

#### Initiative 1.3 报告阅读流从“研究过程型”改为“业务结论型”

- 优先级：P0
- 当前问题：报告正文仍暴露过多研究过程、证据可信度说明和工具执行痕迹，业务人员需要自己从过程里推理结论，阅读负担过高。
- 改造原则：
  - 主报告只保留业务结论、风险判断、授信动作和核查要点。
  - 证据、可信度、工具过程默认折叠展示，放在正文引用和附录中，不抢正文主线。
  - 对公开资料不足但已有线索的场景，允许使用“基于现有资料推断”“疑似”“暂未见明确异常”“需核实”等审慎表达，而不是把章节写成“证据不足，请自行判断”。
  - 不确定性要服务于信贷动作，例如“作为授信前置条件补充”“建议额度释放前核验”，而不是单独堆数据边界。
- 验收标准：
  - 报告第一屏不出现 Research Plan、Claim-Evidence、工具调用、搜索过程等过程化词汇。
  - 每个专项章节先给 2-4 条明确判断，再给核查要点。
  - 正文中的证据默认折叠为“查看依据”，不展开占据主阅读流。
  - 数据不足时仍输出审慎结论和下一步信贷动作，不让用户自行拼结论。

#### Initiative 1.2 信贷建议结构化

- 优先级：P0
- 当前问题：建议有时泛泛而谈，缺少额度、期限、担保、前置条件。
- 改造内容：
  - `credit_decision` 固定输出：准入结论、额度建议、期限建议、担保建议、提款前置、贷后监控。
  - 每条建议绑定 evidence refs 或 data boundary。
  - 缺少数据时输出“暂不建议测算额度”，不能编造金额。
- 验收标准：
  - 每份完整尽调报告都有结构化信贷建议。
  - 建议中不出现无证据的大额授信数字。
  - 前置条件和待补充材料能对应起来。

### Outcome 2：让每个关键结论可追溯

Outcome statement：Enable 客户经理 and 审查人员 to 直接看到每句话背后的来源、可信度和复核状态 so that 报告从“AI 生成文本”升级为“可审计工作底稿”。

#### Initiative 2.1 正文级 Evidence 引用标准化

- 优先级：P0
- 当前状态：已初步完成 `summary_citations` 和正文引用展示。
- 后续改造内容：
  - 引用格式统一为 `[E12] 来源名称 · 可信等级 · 置信度 · 复核状态`。
  - 鼠标悬停或展开可查看证据摘要、URL、抓取时间、字段值。
  - 引用点击定位到证据附录。
- 验收标准：
  - 章节 summary、finding、四维评分、信贷建议均能看到支撑证据。
  - 无 evidence 的结论必须显示“需人工复核/证据不足”。
  - 附录证据编号和正文引用一致。

#### Initiative 2.2 Evidence 分级规则产品化

- 优先级：P0
- 当前问题：证据有 `trust_level/confidence`，但用户不一定理解。
- 改造内容：
  - 定义证据等级：权威源、上市公告/年报、客户上传、内部知识库、公开搜索、LLM 生成。
  - 报告页用清晰标签显示：高可信、中可信、线索参考、需复核。
  - 对公开搜索证据强制加“线索参考”提示。
- 验收标准：
  - 用户能区分“正式证据”和“搜索线索”。
  - 低可信 evidence 不允许支撑高确定性结论。

#### Initiative 2.3 Claim-Evidence 附录升级为审计视图

- 优先级：P1
- 改造内容：
  - 以 claim 为主视角展示：结论、风险等级、证据、缺口、人工复核状态。
  - 支持按章节/风险等级/证据可信度筛选。
  - 展示“未被正文引用的证据”和“无证据支撑的正文”。
- 验收标准：
  - 审查人员能快速定位报告中所有风险结论的证据来源。
  - 可以发现孤立 evidence 和孤立 claim。

### Outcome 3：让工商/司法从搜索摘要升级为字段级风控报告

Outcome statement：Enable 客户经理 to 查看稳定的工商/司法字段和风险标签 so that 主体风险判断不依赖泛泛搜索摘要。

#### Initiative 3.1 工商字段级表格

- 优先级：P0
- 改造内容：
  - 标准字段：统一社会信用代码、法定代表人、注册资本、成立日期、经营状态、经营范围、股东、对外投资、异常经营、行政处罚。
  - 每个字段显示值、来源、可信度、更新时间、是否需复核。
  - 避免证券页面污染工商字段。
- 验收标准：
  - 报告工商章节首先展示字段表，而不是自然语言段落。
  - 字段缺失时显示“未取得”，不填假值。

#### Initiative 3.2 司法线索结构化

- 优先级：P0
- 改造内容：
  - 标准字段：案件类型、案号、案由、金额、法院/处罚机关、时间、当前状态、来源链接。
  - 区分裁判文书、被执行、失信、行政处罚、监管问询、重大舆情。
  - 对上市公司重点检索公告中的诉讼/处罚/监管问询。
- 验收标准：
  - 司法章节能看到线索明细表。
  - 无权威源时不能输出“无司法风险”，只能输出“公开搜索未发现，需权威复核”。

#### Initiative 3.3 权威源接入占位与成本提示

- 优先级：P1
- 改造内容：
  - 为工商/司法正式 API 预留 provider adapter。
  - 报告中标识当前使用的是“公开资料预尽调”还是“权威源增强”。
  - 高成本调用前支持人工确认或策略控制。
- 验收标准：
  - 同一字段可从公开搜索切换到权威 API。
  - Evidence 保留 provider、调用时间、成本估算。

### Outcome 4：让行业分析像投研判断，而不是行业科普

Outcome statement：Enable 客户经理 to 理解目标公司所处行业周期、竞争地位和还款来源压力 so that 行业章节能支撑期限、额度和贷后监控设计。

#### Initiative 4.1 行业子赛道精准识别

- 优先级：P0
- 改造内容：
  - 结合经营范围、主营构成、年报经营讨论、公告、搜索线索识别行业。
  - 对上市公司优先使用年报主营构成和业务描述，不只靠关键词。
  - 输出标准行业、授信分析行业、子赛道标签。
- 验收标准：
  - 士兰微不能识别成贸易/进出口。
  - 药明康德应识别为 CXO/CDMO/医药外包相关子赛道。
  - 行业章节显示识别依据。

#### Initiative 4.2 行业诊断结构固定化

- 优先级：P0
- 改造内容：
  - 每个行业章节固定包含：行业定位、周期判断、竞争格局、政策环境、上下游、授信关注点。
  - LLM 必须基于 evidence 和 RAG 知识写诊断，不允许泛泛表述。
  - 低质量 LLM 输出触发 fallback，但 fallback 也要按行业类别区分。
- 验收标准：
  - 每个行业诊断段至少有 1 个证据引用。
  - 禁用“竞争激烈、政策利好、技术更新快”等无锚点表达。
  - 行业章节不串场。

#### Initiative 4.3 同业对标与授信传导

- 优先级：P1
- 改造内容：
  - 引入 2-3 个同业公司或行业基准。
  - 输出行业风险如何传导到收入、毛利率、现金流、应收账款、资本开支。
  - 形成贷后监控指标。
- 验收标准：
  - 行业分析不只说行业好坏，还能说明对授信期限和还款来源的影响。

### Outcome 5：让财务分析从描述性变成诊断性

Outcome statement：Enable 客户经理 to 识别财务数据背后的异常信号 and 核查动作 so that 财务章节能用于贷前风险判断。

#### Initiative 5.1 财务诊断 prompt + RAG 动态注入

- 优先级：P0
- 当前状态：已注入财务领域知识，仍需稳定提高 LLM 命中率和质量。
- 改造内容：
  - 把财务勾稽规则、异常信号、行业阈值通过 RAG 动态注入 prompt。
  - LLM 输出结构化 JSON：phenomenon、driver、risk_level、verification_actions、missing_items、evidence_refs。
  - 每段分析必须覆盖近三年趋势，而不是只看最近一年。
- 验收标准：
  - 财务章节从“指标拼接”变成“现象-归因-风险-核查”。
  - 每段都能看到数据来源和证据引用。

#### Initiative 5.2 财务质量闸门

- 优先级：P0
- 改造内容：
  - 检查未授权数字、术语错误、年度缺失、只分析一年、句子不通、数据矛盾。
  - 失败时重新生成或进入专业 fallback。
  - 前端显示 LLM/fallback 来源和质量告警。
- 验收标准：
  - 不再出现“资产持有率”“经营活动量净额”等错误术语。
  - LLM 输出不可用时，用户知道用了 fallback。

#### Initiative 5.3 非上市财报上传资料室化

- 优先级：P1
- 改造内容：
  - 三大表上传从单次动作升级为材料清单：待上传、已解析、已采信、需复核。
  - 支持多文件、多年度、重新上传和解析报告。
  - 上传材料进入 Evidence Store。
- 验收标准：
  - 非上市企业报告能清楚展示哪些财务结论来自上传文件。

### Outcome 6：让 HITL 从确认按钮升级为尽调协同

Outcome statement：Enable 客户经理 to 在关键节点确认计划、补充资料和确认数据边界 so that Agent 输出能被人类审查流程接管。

#### Initiative 6.1 计划确认增强

- 优先级：P0
- 当前状态：已有计划确认中断。
- 改造内容：
  - 展示每个研究问题的证据需求、工具路线、预估成本/耗时。
  - 用户可以删除、补充、调整研究问题。
  - 确认后冻结计划版本。
- 验收标准：
  - 计划确认不是只有“确认继续”，而是可编辑研究计划。

#### Initiative 6.2 证据缺口确认增强

- 优先级：P0
- 当前状态：已有二轮补证后缺口确认。
- 改造内容：
  - 缺口按章节分组展示。
  - 每个缺口对应建议补充材料。
  - 用户确认后报告中保留人工确认记录。
- 验收标准：
  - 点击“确认边界并生成报告”后，报告中能看到人工确认说明和缺口边界。

#### Initiative 6.3 资料室式待补充清单

- 优先级：P1
- 改造内容：
  - 汇总所有待补充材料：财报、合同、流水、纳税、征信、诉讼说明、权威工商报告。
  - 每项材料有状态、责任人、备注。
  - 报告页和执行页都能看到材料缺口。
- 验收标准：
  - 报告不仅告诉用户“缺数据”，还告诉用户“缺什么、为什么、补了以后影响哪条结论”。

### Outcome 7：让执行页体现研究智能体能力

Outcome statement：Enable 用户 to 看到 Agent 如何规划、检索、反思和补证 so that 产品不像普通报表生成器，而像真实研究智能体。

#### Initiative 7.1 Plan-Execute 时间轴增强

- 优先级：P1
- 当前状态：已有计划、工具调用、二轮补证展示。
- 改造内容：
  - 时间轴分段：计划生成、计划确认、首轮检索、证据评估、二轮补证、报告合成、人工确认。
  - 每段展示输入、工具、输出、耗时、失败/降级。
- 验收标准：
  - 用户能看出 Sequential Thinking MCP、LLM Planner、Bocha、RAG、crawl4ai 是否参与。

#### Initiative 7.2 工具调用可观测

- 优先级：P1
- 改造内容：
  - 展示每个工具调用的 provider、query、命中数、耗时、是否成功。
  - 外部工具失败时明确展示降级路径。
- 验收标准：
  - 用户不再问“你真的调用搜索工具了吗”。

### Outcome 8：让报告可交付

Outcome statement：Enable 客户经理 to 导出、分享和沉淀报告 so that DDG-Agent 输出能进入真实业务流程。

#### Initiative 8.1 DOCX/PDF 导出

- 优先级：P1
- 改造内容：
  - 支持报告导出 PDF/DOCX。
  - 保留正文证据引用编号和证据附录。
  - 保留数据边界和人工确认记录。
- 验收标准：
  - 导出的报告不丢失 evidence refs。
  - 格式接近银行客户经理报告。

#### Initiative 8.2 报告版本与任务持久化

- 优先级：P0（生产化阻断）
- 当前问题：后端重启会丢内存任务。
- 改造内容：
  - 任务、报告、evidence、interrupt、human_action 持久化。
  - 支持报告版本记录和重新生成。
- 验收标准：
  - 后端重启后仍能打开历史报告。

## 四、优先级总表

| 优先级 | 任务 | 用户价值 | 实现复杂度 | 建议顺序 |
| --- | --- | --- | --- | --- |
| P0 | 报告页改成贷前尽调主线 | 高 | 中 | 1 |

## 五、推荐推进节奏

### 第一阶段：报告可信度

目标：让报告看起来像客户经理能用。

- 报告页改成贷前尽调主线。
- 正文级 Evidence 引用标准化。
- 财务质量闸门。
- 行业诊断结构固定化。

### 第二阶段：专项可信度

目标：让四个专项不再像泛泛搜索总结。

- 工商字段级表格。
- 司法线索结构化。
- 行业子赛道精准识别。
- 财务 RAG 动态注入。

### 第三阶段：协同与可观测

目标：让用户知道 Agent 做了什么，也知道哪里需要人工补。

- 计划确认增强。
- 证据缺口确认增强。
- 工具调用可观测。
- 资料室式待补充清单。

### 第四阶段：生产化交付

目标：从 PoC 进入试点/上线候选。

- 任务与报告持久化。
- 报告版本管理。
- DOCX/PDF 导出。
- 权限、审计、限流、监控。
