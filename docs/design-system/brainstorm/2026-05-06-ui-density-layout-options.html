信贷工作台 · 降噪与版式：三种骨架方向

对照 docs/UNIFIED_VISUAL_MASTERPLAN.md 与 docs/UI_DESIGN_SPEC.md： 目标是降低首屏焦点数量、统一主栏 / 侧栏比例、减少重复 KPI 与装饰渐变。 下面是三种可落地的重构路径（可先选方向，再按导航顺序逐页收敛）。

方案 A · 渐进披露（折叠 / 分段）

推荐起步：见效快

首屏只保留「任务列表 + 一句 AI 摘要 + 最多 3 个 KPI」。次要模块默认折叠或放到 Tabs。

PageHeader（≤3 KPI）
任务列表（主焦点）
次要区块 ▸ 默认折叠
侧栏 360–400
优点
  • 改动集中在页面结构，不动业务逻辑
  • 立刻降低信息密度
代价
  • 需要设计「默认展开」规则
  • 折叠过多可能藏关键入口

方案 B · 模板硬化（布局组件强制执行）

推荐中期：一致性最强

把 MainLayout + PageHeader + SplitPane 做成唯一合法骨架：固定最大宽 1600、外边距断点、侧栏宽度、区块间距 24。

Shell（max-w + px 断点）
SectionHeader × N（统一）
固定侧栏
优点
  • 跨页一致，切页不断裂
  • 后续迭代成本低
代价
  • 需要调整多数页面 markup
  • 短期 PR 体积较大

方案 C · 混合（A + B 分期）

推荐默认（平衡风险）

第一轮：全局 token / 间距 / PageHeader KPI 上限 / 侧栏宽度（骨架）。第二轮：按导航顺序逐页「折叠次要模块 + 合并重复 KPI」。

M1：tokens + layout shell
M2：Dashboard → Data → Analysis → …
优点
  • 风险可控、可阶段性验收
  • 对齐 SDD 与舒适度自检
代价
  • 周期更长
  • 需维护任务清单
