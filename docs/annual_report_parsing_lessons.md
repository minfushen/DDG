# DDG Agent 年报 PDF 解析 + 全量入库踩坑记录

> 记录对象：上市公司年报 PDF（以三安光电 600703 2022/2023/2024 年年报为例）
> 目的：将合同审查项目中的 PDF 解析与索引入库经验，迁移到对公尽调场景的年报解析链路中，沉淀可复现的坑与解法。

---

## 〇、年报 PDF 结构特征（先摸清地形）

| 特征 | 说明 |
|---|---|
| 封面 + 扉页 | 股票代码、公司简称、报告年度、审计机构，页眉通常带"600703 2023 年年度报告" |
| 目录页 | 章节标题 + 页码，带大量省略号 |
| 正文表格 | 三大表（资产负债表、利润表、现金流量表）、业务分部表、存货/应收账款明细表 |
| 表格特点 | 跨页频繁、合并单元格、列宽不均、数字列右对齐 |
| 附注 | 层级缩进明显，如 `（一）重要会计政策` → `1. 收入确认` → `（1）...` |
| 页眉页脚 | `"公司代码：600703 公司简称：三安光电"`、页码、交易所声明 |
| 扫描件/印章 | 审计报告页可能为扫描件，带红章 |
| 同名章节 | "重要事项"、"董事会报告"、"财务报告"等在目录和正文中重复出现 |

**结论**：年报解析不能只用 `extract_tables()`，必须结合**版面分析 + 状态机 + 结构化校验**。

## 一、PDF 解析踩坑

### 坑 1：目录页和页眉页脚被识别为正文内容

- **现象**：解析结果里混入"公司代码：600703 公司简称：三安光电"、"第 X 页"、目录省略号行。
- **根因**：页眉页脚在每一页重复出现，目录行 `第三节 管理层讨论与分析 ......... 45` 也匹配章节正则。
- **解法**：
  1. 过滤页眉关键词：`公司代码`、`公司简称`、`年度报告`、`巨潮资讯`。
  2. 过滤目录省略号行：`\.{3,}\s*\d+\s*$`。
  3. 对每页固定位置（顶部 5%、底部 5%）的重复文本做去重。

### 坑 2：pdfplumber 表格抽取列错位

- **现象**：`page.extract_tables()` 把一页资产负债表切成多张表，"流动资产"内容错位到"非流动资产"列，年末余额错成年初余额。
- **根因**：
  - 跨页表格没有合并，pdfplumber 把表头在每页重复识别。
  - 窄列（如"序号"）宽列（如"附注"）混合，列边界推断错误。
  - 合并单元格导致某行列数少于其他行，强制对齐后数据偏移。
- **解法**：
  - 放弃纯表格抽取，改用 **PyMuPDF 版面分析 + pdfplumber 表格修复** 的混合方案。
  - 对跨页表格做行对齐：根据表头关键词（如"资产""负债""期末余额"）识别表格起止。
  - 数值校验：同一行"年初余额 + 本期增加 - 本期减少 = 期末余额"不成立时标记异常。

### 坑 3：科目名称 vs 金额 vs 附注说明误判

- **现象**："应收账款"被识别成金额，"1,234,567.89"被识别成科目名，附注说明被当成新科目。
- **根因**：初版用"长度启发式"：长的是说明、短的是科目、带数字的是金额。但"一年内到期的非流动资产"（14 字）是科目，"其中：利息费用"（7 字）是说明。
- **解法**：改用多维信号：
  - 位置信号：科目在表格左列，金额在右列。
  - 格式信号：金额含逗号、小数点、负号；科目不含纯数字。
  - 缩进信号：附注说明相对于主科目缩进。
  - 语义信号：维护标准科目词典做匹配。

### 坑 4：长科目名称折行被切成多个碎片

- **现象**："一年内到期的非流动资产"被切成"一年内到期的"、"非流动资产"两行，重建时只保留后半。
- **根因**：窄列放不下长科目名，PDF 渲染时折行，但 pdfplumber 把每行当独立单元格。
- **解法**：
  - 行连续性判断：当前行左对齐、下一行也左对齐、且下一行不是标准科目开头 → 拼接为同一科目。
  - 标准科目词典兜底：遇到碎片时 fuzzy match 完整科目名。

### 坑 5：页码数字被识别为金额/序号

- **现象**：资产负债表第 100 页的内容里，页码"100"被识别成一行金额数据。
- **根因**：页码通常位于页面底部居中，但某些页面版式下会与正文表格底部对齐，被状态机误判。
- **解法**：
  - 空白行在循环顶部 `if not line: continue`。
  - 每页首行/末行的纯数字，若与页面页码一致则跳过。
  - 结合位置信息：页码通常在固定 y 坐标区域。

### 坑 6：附注折行"等。"被误判为新条目

- **现象**：附注 `(1) 坏账准备计提方法等。` 的"等。"换行后顶格，被状态机当成新的附注条目。
- **根因**：表现形式/附注内容换行后有时不缩进，状态机根据缩进判断失效。
- **解法**：增加 `in_note` 状态——一旦进入附注说明区，后续顶格续行仍归为当前附注，直到下一个编号或新一级标题出现。

### 坑 7：扫描件/印章页 OCR 噪声

- **现象**：审计报告页盖有红章，OCR 把印章识别成乱码字符，混入正文。
- **根因**：审计报告签字页、财务报表附注中的扫描图片，普通文本提取会漏掉或产生噪音。
- **解法**：
  - 对纯图像页面（text 极少或为空）走 OCR 前先降噪、纠偏、二值化。
  - 对印章区域做颜色过滤（红色通道抑制）。
  - OCR 结果用版面分析重新推断文本顺序。

### 坑 8：同名章节合并导致内容丢失

- **现象**："重要事项"在目录、董事会报告、财务报告多处出现，按标题去重后只保留一章，其余内容丢失。
- **根因**：目录、正文、附注中存在同名标题，按简单 title 去重会误删。
- **解法**：章节 key 加入**层级路径 + 页码范围**，如 `正文/第三节/重要事项/P45-48` 与 `目录/重要事项/P3` 视为不同章节。

### 解析阶段最终质量

- 输出：结构化三大表 + 关键财务指标 + 附注层级树
- 准确率：科目识别 > 95%，跨页表格合并 > 90%，数值校验异常标记 < 5%
- 已知微瑕：少数非标准科目名称仍需人工复核；复杂嵌套表格（如分部报告）偶有错位

## 二、全量入库踩坑

### 坑 9：BM25 索引被后续批次覆盖

- **现象**：先 `index_annual_reports()` 再 `industry_knowledge_base()`，BM25 只能搜到行业知识库，向量却能搜到年报——两路召回不一致。
- **根因**：`index_documents()` 每次 `self.bm25.index(documents)` 整体替换 BM25 索引，而向量索引是累加的。
- **解法**：抽取 `collect_*_docs()` 收集全部语料，**一次性合并后单次 `index_documents`**，确保 BM25 与向量覆盖同一批文档。

### 坑 10：Embedding 成本过高

- **现象**：单份年报 200+ 页，按父子文档分片后产生 300-500 个子块，首跑需数十次 Embedding API 调用。
- **根因**：每段文本都重新编码，且年报页数多、chunk 小。
- **解法**：
  - 增加磁盘缓存（按文本 MD5 存 embedding_cache）。
  - 对表格数据优先结构化提取，减少无意义 chunk。
  - 首次构建 10-20s；缓存命中重建 0.5s、零 API 调用。

### 坑 11：索引不落盘，每次重启重算

- **现象**：引擎索引在内存，API 每次请求都重建，冷启动慢、反复消耗 embedding 额度。
- **解法**：新增 `save_index()` / `load_index()`（pickle 文档 + 向量 + 父子映射 + BM25 状态）。
  - 单企业索引落盘 5-10MB，重载 < 0.5s（vs 构建 10-20s）。

### 坑 12：行业类型过滤严格导致返回空

- **现象**：用户问"三安光电 LED 业务风险"，过滤 `industry="LED"` 后返回空，但知识库里有"光学光电子行业"、"第三代半导体"。
- **根因**：严格子串匹配 `filter not in doc_type`，无法处理"LED ↔ 光学光电子 ↔ 半导体照明"等同义/近义关系。
- **解法**：新增 `_industry_match()`——双向子串 + 别名映射 + 去噪匹配（剥掉"行业""产业""板块"），并维护行业别名表：
  - `LED` → `光学光电子`、`半导体照明`
  - `第三代半导体` → `氮化镓`、`碳化硅`、`化合物半导体`

### 坑 13：API 每次请求重建索引

- **现象**：`/api/v1/tasks/{id}/report` 原先每次都新建 `HybridSearchEngine()` 并重新索引，单次请求就烧一遍 embedding。
- **解法**：`api/routes.py` 改为**单例引擎** `get_engine()`（惰性加载落盘索引，缺失时现场构建并落盘）+ `@app.on_event("startup")` 启动即加载。

### 坑 14：chunk 切分过细导致上下文断裂

- **现象**：年报中的"关联交易"说明被切成多个短 chunk，检索时只召回片段，无法还原完整交易背景。
- **根因**：固定长度切分（如每 512 token）不考虑语义边界。
- **解法**：
  - **父子文档分片**：检索用短子块，输入时拉回完整父段落。
  - 按自然段落/表格行切分，不在句子中间截断。
  - 对跨页连续内容做合并标记。

### 坑 15：时间维度缺失导致跨年对比失效

- **现象**：检索"三安光电 2023 年毛利率"时召回 2022 年数据，因为 chunk 里没有年份元数据。
- **根因**：chunk 元数据只包含章节标题，没有时间戳/报告年度。
- **解法**：在 chunk metadata 中注入 `report_year`、`report_period`、`page_number`、`source_file`，检索时按年份过滤或重排序。

## 五、与合同审查项目的核心差异

| 维度 | 合同风险清单 PDF | 上市公司年报 PDF |
|---|---|---|
| 核心结构 | 四列表格 + 目录 | 三大表 + 附注 + 目录 |
| 关键判别信号 | 缩进 | 列位置 + 数字格式 + 层级缩进 |
| 噪声来源 | 页眉"法天使"、目录省略号 | 页眉公司代码、页码、审计声明 |
| 表格难度 | 窄列折行、列错位 | 跨页表格、合并单元格、分部报告 |
| 入库重点 | 风险点/表现形式分片 | 科目/金额/附注/年度元数据 |
| 检索重点 | 合同类型匹配 | 报告年度 + 行业别名匹配 |

---

**一句话总结**：年报 PDF 解析的坑集中在"表格跨页与列对齐 + 页眉页脚噪声 + 科目/金额/附注判别"，全量入库的坑集中在"索引一致性 + embedding 成本 + 年度/行业元数据 + 单例化"，解法与合同审查项目同源，但对财务结构化精度的要求更高。
