# 13 DDG-Agent 正式上线 readiness checklist

本文基于 `pre-mortem`、`test-scenarios`、`shipping-artifacts` 三类 PM skill 方法整理，用于判断 DDG-Agent 从 PoC/MVP 走向正式上线还缺哪些必备项。

## 一、上线结论

当前项目适合继续作为 PoC、演示环境、内部试点和面试项目展示；如果要面向真实银行客户或外部 SaaS 用户正式上线，仍不建议直接发布。

核心原因不是功能链路没有跑通，而是生产化能力还不足：任务状态存储、权限隔离、审计留痕、成本控制、质量闸门、监控告警、测试覆盖和数据合规尚未达到正式系统标准。

## 三、Tigers：真实上线风险

### 1. 报告可信度风险

风险：用户最敏感的问题是报告“像不像客户经理能用”。只要出现一眼假的结论、错误行业、模拟数据、无证据高置信判断，产品信任会迅速崩塌。

缓解：

- 设置报告生成前质量闸门：无 evidence 不允许输出确定性结论。
- 对工商、司法、行业、财务四类结论分别设置最低证据覆盖率。
- 报告正文中展示“证据支撑了哪句话”，不是只在附录堆证据。
- 明确区分“公开资料预尽调”“财报增强尽调”“正式授信尽调”。

### 2. 任务不可恢复风险

风险：当前任务状态主要在内存中，服务重启、进程崩溃、并发执行都会导致任务丢失或状态错乱。

缓解：

- 将 task、event、interrupt、research_state、report 持久化。
- 引入任务状态机表，状态变更写审计日志。
- LangGraph checkpoint 接入 SQLite/PostgreSQL/Redis，支持 resume。

### 3. 多租户与权限风险

风险：正式 SaaS 或私有化多部门使用时，报告、财报、搜索记录、客户材料可能被越权访问。

缓解：

- API 入口增加认证中间件。
- 所有任务数据增加 `tenant_id/user_id/project_id`。
- SSE、报告查看、材料上传、任务恢复全部做资源归属校验。

### 4. 外部工具成本和稳定性风险

风险：Bocha、Exa、Tavily、crawl4ai、LLM、MCP 都可能慢、贵、失败或返回低质量内容。

缓解：

- 统一 Tool Gateway：超时、重试、熔断、缓存、成本统计、黑白名单。
- 对高成本工具设置调用前审批或任务预算。
- 记录每次工具调用输入、输出摘要、耗时、费用估算、错误。

### 5. 数据源合规风险

风险：公开搜索内容、上市公司公告、裁判文书、工商信息、用户上传财报的使用边界不同，正式上线必须可解释、可追溯。

缓解：

- 建立 source policy：权威源、公开源、用户上传、RAG、LLM 生成分级。
- 报告中输出数据边界和来源说明。
- 对外部网页抓取保留 URL、抓取时间、摘要、置信度。

## 四、Fast-follow checklist

这些事项可以不阻断小范围试点，但 30 天内必须补齐。

| 模块 | 检查项 | 目标 |
| --- | --- | --- |
| HITL | 计划确认、缺口确认、财报上传已经有雏形 | 迁移为 LangGraph interrupt/checkpoint/resume |
| RAG | 知识库最小闭环已接入 | 增加知识命中解释、版本号、知识过期提示 |
| 报告导出 | 当前主要是页面展示 | 支持 DOCX/PDF 导出、模板化、版本留存 |
| 前端状态 | 执行页和报告页已有 DeepResearch 展示 | 增加失败重试、断线恢复、任务历史、报告版本列表 |
| 工具观测 | 部分来源信息已经进入 evidence | 前端展示每个结论的来源、置信度、复核状态 |
| 行业知识 | 已注入行业/财务领域知识 | 建立行业子赛道规则库和高质量 few-shot 样例库 |
| 私有化适配 | 文档已说明 SaaS/私有化分叉 | 提供数据源适配器接口和客户自购数据源接入规范 |

## 五、Paper Tigers：看起来吓人但不是当前最大风险

| 担忧 | 判断 |
| --- | --- |
| 必须立即上 CrewAI | 不是必须。当前更关键是 evidence、状态机、报告质量和数据源治理。CrewAI 可作为综合审查层，而不是核心依赖。 |
| 必须一次性完整迁移 LangGraph | 不必。当前 LangGraph shell 已经有价值，原生 interrupt/checkpoint 可以在节点契约稳定后再迁。 |
| 必须接所有工商/司法权威 API 才能上线试点 | 小范围试点可以先用公开搜索 + 人工复核，但正式授信场景必须接权威数据源。 |
| 必须让 LLM 负责所有判断 | 不应如此。正式系统应由结构化取数、规则、RAG、LLM 共同完成，LLM 负责诊断表达和假设生成。 |

## 六、Elephants：团队需要尽快讨论但目前不够明确

| 问题 | 为什么重要 | 建议动作 |
| --- | --- | --- |
| 产品定位到底是“预尽调助手”还是“正式授信报告生成器” | 两者的数据要求、合规责任、报告语气完全不同 | 明确首发版本只承诺预尽调，正式授信必须人工复核 |
| SaaS 版与私有化版是否共用同一后端架构 | SaaS 更适合 Dify/平台化，私有化更适合 LangGraph/FastAPI | 输出双架构路线和能力差异表 |
| 真实客户经理如何验收报告 | 如果验收标准不清，报告优化会长期靠体感 | 收集 5-10 份真实脱敏报告，建立评分 rubric |
| 外部搜索失败时是否允许出报告 | 允许则必须明确数据边界；不允许则任务成功率受影响 | 按报告模式制定输出策略 |
| 模型供应商切换策略 | 金融客户常要求私有化或国产模型 | 抽象 Model Gateway，支持主备模型、质量评测和回退 |

## 七、核心测试场景 checklist

### A. 首页创建任务

- 输入完整公司名，能在 1 秒左右创建 task_id 并进入执行页。
- 输入“分析一下士兰微这家上市公司”，主体识别为“士兰微”或对应上市主体，不携带任务话术。
- 输入简称、证券简称、股票代码，系统能提示确认主体或自动映射。
- 后端 502/超时时，前端展示可理解错误，不白屏。

### B. 计划生成与人工确认

- LLM Planner 成功时，展示研究问题、证据需求和工具路线。
- Planner 失败时，降级到规则计划，并明确标注 fallback。
- 页面必须出现“确认计划并执行”按钮，点击后任务继续。
- 用户补充研究要求后，计划能被记录并进入后续执行。

### C. 工具调用与证据生成

- Bocha 搜索命中公告/财报/行业资料时，生成 evidence。
- Exa MCP 可用时，作为备用搜索/页面抓取通道。
- crawl4ai 未安装或失败时，任务不崩溃，evidence 标明正文抓取失败。
- 每条 evidence 包含 source、source_type、trust_level、confidence、requires_manual_review。

### D. 财务分析

- 上市公司能获取近三年核心财务指标并生成诊断段落。
- 非上市未上传财报时，报告进入公开资料预尽调模式，不伪造财务结论。
- 上传三大表后，毛利率、净利率、资产负债率、经营现金流等来自文件。
- LLM 生成财务诊断失败时，fallback 文案必须专业、通顺、无错误术语。

### E. 行业分析

- 半导体、新能源、消费、制造、贸易等典型行业不串场。
- 行业结论包含行业定位、周期判断、竞争格局、授信关注点。
- 行业识别不能只靠经营范围关键词，需结合主营构成、公告和搜索线索。
- 每段行业诊断至少绑定来源或明确“需补充”。

### F. 工商与司法分析

- 工商字段抽取不能被证券页面污染。
- 司法搜索需区分裁判、执行、失信、行政处罚、舆情线索。
- 公开搜索不可用时，不能生成确定性“无风险”结论。
- 权威源和普通网页源需要分级展示。

### G. 报告页

- 报告不是研究摘要，而是贷前尽调报告结构。
- 每个关键结论旁展示 evidence refs。
- 明确显示报告模式、数据边界、待补充材料。
- 显示 LLM/fallback 来源、工具调用来源和人工复核状态。

### H. 失败与恢复

- 后端重启后，未完成任务可以恢复。
- SSE 断开后，刷新页面能获取当前任务状态。
- 外部工具超时不会卡死整个任务。
- 人工确认中断状态刷新后仍能看到按钮和上下文。

## 九、上线里程碑建议

### M0：内部演示可用

- 首页创建任务稳定。
- 计划确认按钮可用。
- 至少 5 家上市公司完整链路跑通。
- 报告没有明显语病、串场、模拟数据污染。

### M1：小范围试点可用

- 任务状态持久化。
- 证据链前端可见。
- 报告质量闸门上线。
- 接入基础监控和日志。
- 支持导出报告。

### M2：正式上线候选

- 用户、租户、权限、审计完整。
- CI/CD、Docker、环境隔离完整。
- 关键链路自动化测试覆盖。
- Tool/Model Gateway 支持限流、成本、熔断、缓存。
- 数据合规和安全评审通过。

### M3：银行客户生产级

- 接客户自购工商、司法、行政处罚、征信、财报数据源。
- RAG 接入内部授信制度、行业政策、评级模型和案例库。
- LangGraph checkpoint + interrupt 正式替代内存 HITL。
- 形成客户经理验收标准和报告质量评分体系。

## 十、最小下一步

建议下一步优先做三件事：

1. 任务状态持久化增强：当前已用 SQLite 保存 task/report/interrupt JSON 快照，下一步补任务列表、过期清理和生产级 PostgreSQL/Redis 方案。
2. 报告质量闸门：上线前阻断 mock、无证据结论、行业串场、未授权数字。
3. 权限与审计骨架：即使先做单用户，也要在数据模型里预留 `tenant_id/user_id/audit_log`。
