# 业务价值盘点

> 本文档从**业务问题**视角盘点 DDG-Agent 的实际产出效果，不堆技术组件。
> 所有数据来自 6 家上市公司、25 份真实尽调报告的质量评测结果。
> 最近更新：2026-07-19

---

## 一、产品定位（一句话）

> **把银行客户经理 2–5 天的对公尽调报告，压缩到 5 分钟自动生成，且每条结论可追溯到原始证据来源。**

交付形态是 API/SDK，嵌入银行现有信贷系统，不是另卖一个平台。

---

## 二、解决的业务问题

### 问题 1：尽调报告耗时长

| | 传统流程 | 本系统 |
|---|---|---|
| 耗时 | 客户经理手写 2–5 天 | **3–8 分钟自动生成** |
| 产出 | 一份初稿，需反复修改 | 结构化报告 + 证据链 + 缺口清单 |

**实测数据**（6 家上市公司完整尽调）：

| 公司 | 执行耗时 | 证据数 | 工具调用 |
|---|---|---|---|
| 三安光电 | 7.1 分钟 | 200 条 | 27 次 |
| 亿纬锂能 | 7.9 分钟 | 217 条 | 28 次 |
| 卓胜微 | 3.5 分钟 | 211 条 | 26 次 |
| 欣旺达 | 4.8 分钟 | 317 条 | 31 次 |
| 药明康德 | 4.9 分钟 | 124 条 | 19 次 |
| 蓝思科技 | 3.2 分钟 | 115 条 | 15 次 |

### 问题 2：AI 报告黑盒，风控不敢引用

传统 LLM 生成报告是"一坨文本"，风控审查员无法追溯结论来源。

**本系统的做法**：每条结论绑定证据 ID，报告正文带正文级引用，可跳转到原始财报页码、公告 URL 或知识库条目。

**实测数据**：
- 每份报告生成 5–7 条结构化结论声明（Claim），每条绑定 evidence_ids
- 证据来源类型覆盖 6+ 类：CodeAct 财务指标计算、上市公司公开资料、权威公告源、公开财报、内部知识库、公开搜索线索
- 高可信证据占比 **67–75%**（high/authoritative 级别）
- 引用密度评分 100 分（满分），证据深度评分 100 分（满分）

### 问题 3：客户经理报告"太粗浅"（信贷岗副总原话）

> "一线客户经理产出的初版尽调报告太粗浅、不专业，希望深度向信贷/风控部门的专业水准看齐。"

**具体表现与解决**：

| 粗浅表现 | 本系统解决方式 | 效果 |
|---|---|---|
| 只堆数字，不做同业对比 | 按申万行业取同行业 A 股中位数对标 | 财务深度评分 80 分 |
| 缺趋势归因 | 多期真实趋势 + 杜邦式数据驱动归因 | 每个异常含"现象—归因—风险—核查" |
| 缺盈利质量分析 | 扣非 vs 归母、非经常性损益、政府补助依赖度 | 显式输出盈利质量维度 |
| 行业分析直接缺失或泛化 | 行业分类代码 + LLM 裁判 + RAG 知识库 | 行业深度评分 80 分，6 家全部正确识别细分行业 |

### 问题 4：行业识别错误导致风险判断偏移

> 士兰微曾被误识别为"贸易/进出口"（因经营范围含"货物进出口"），导致行业风险分析完全跑偏。

**解决**：规则召回候选 + 上市公司映射 + LLM 语义裁判 + 主营构成校验。

**实测结果**（6 家公司 0 错分）：

| 公司 | 正确识别行业 | 标准路径 |
|---|---|---|
| 三安光电 | 半导体与光电子器件 | 制造业 > 电子器件制造 > 光电子器件制造 |
| 卓胜微 | 集成电路制造 | 制造业 > 电子器件制造 > 集成电路制造 |
| 亿纬锂能 | 锂离子电池制造 | 制造业 > 电池制造 > 锂离子电池制造 |
| 欣旺达 | 锂离子电池制造 | 制造业 > 电池制造 > 锂离子电池制造 |
| 药明康德 | CXO/CRDMO | 医药研发服务 |
| 蓝思科技 | 电子元器件制造 | 电子元器件制造业 |

### 问题 5：多源数据矛盾人工查不出

不同数据源（巨潮、东方财富）的同一财务指标可能不一致，人工逐项核对不现实。

**解决**：跨源证据一致性校验自动发现超阈值差异，触发二轮补证定向核查。

**真实案例**：欣旺达报告自动发现"公开结构化财报数据源之间存在 3 项超阈值差异"，系统自动生成财务专项补证任务，回查巨潮/交易所原始年报 PDF。

### 问题 6：银行已有智能体平台，但财务/行业能力无法原子化交付

百融 Dify SaaS 平台擅长端到端对话应用，但难以把财务/行业分析拆成可独立调用、可审计的 API。

**解决**：基于 LangGraph 独立实现，财务/行业 Agent 通过标准 REST API 交付，支持被银行内部平台编排调用。

## 四、端到端业务故事（面试可用）

### 案例：三安光电完整贷前尽调

```
输入："三安光电"
  ↓ 3.2 秒意图解析
  ↓ 7.1 分钟自动执行
    · 主体识别：三安光电股份有限公司，证券代码 600703，实控人林秀成（22.65%）
    · 行业识别：半导体与光电子器件（制造业 > 电子器件制造 > 光电子器件制造）
    · 财务分析：营收 179.49 亿，净利润 -3.33 亿，毛利率 12.43%
    · 发现缺口：缺行业增速、库存周期数据
    · 二轮补证：自动生成行业补证任务，定向检索研报和头部公司财报
    · 证据归集：200 条证据，其中 135 条高可信
  ↓ 质量评测：90 分 / A 级 / 通过
  ↓ 输出：8 章结构化授信报告 + 200 条证据链 + 6 条结论声明
  ↓ 授信建议：有条件准入，风险评分 82（低风险）
```

**一句话讲**：输入一个企业名，7 分钟出一份 8 章授信报告，200 条证据可追溯，每条结论绑定原始来源，风控可以直接引用。

### 案例：欣旺达跨源数据差异自动发现

```
首轮执行发现：东方财富与巨潮的财报数据存在 3 项超阈值差异
  ↓ 自动识别为 financial gap（medium severity）
  ↓ 自动生成二轮补证任务：
    "补充核查欣旺达财务专项缺口：公开结构化财报数据源之间存在3项超阈值差异"
  ↓ 定向检索：巨潮资讯 原始年报 PDF 审计报告 附注
  ↓ 补证结果写入 Evidence Store，标记数据边界
```

**一句话讲**：系统自动发现两个数据源的财报数字对不上，自动发起二轮补查去核对原始年报，不用人工逐项排查。

## 五、Bad Case 与迭代过程

### Bad Case 1：士兰微被识别为"贸易/进出口"

| | 详情 |
|---|---|
| 问题 | 经营范围含"货物进出口、技术进出口"，规则匹配误判为贸易行业 |
| 根因 | 纯规则匹配无法区分主营业务和经营范围噪声 |
| 解决 | 规则召回候选 → 注入上市公司映射和公开资料 → LLM 语义裁判 → 输出 ignored_noise |
| 效果 | 士兰微稳定识别为"集成电路制造"，6 家公司 0 错分 |

### Bad Case 2：Rebecca 行业基准是硬编码假值

| | 详情 |
|---|---|
| 问题 | `analyzers.py` 中毛利率 35%、ROE 15%、流动比率 1.5、资产负债率 60% 全部写死 |
| 根因 | 早期开发为快速验证流程，用假值占位 |
| 解决 | 复用 akshare/东方财富按申万行业取同行业 A 股中位数，语义行业名映射到板块成分股 |
| 效果 | 行业对标从假值升级为真实中位数，财务深度评分达 80 分 |

### Bad Case 3：行业场景 Gap 识别缺失

| | 详情 |
|---|---|
| 问题 | DeepResearch 二轮补证机制只有财务和司法的专项 Gap 规则，行业场景缺同业对标、缺主营构成、缺行业 KPI 都不会被识别 |
| 根因 | gap_reflector 未覆盖行业 category |
| 解决 | 新增 6 条专项 Gap 规则（行业 4 条 + 财务 2 条），follow_up_planner 按缺口类型生成精准检索词 |
| 效果 | 行业场景能自动识别业务级缺口并定向补查，二轮补证真正下沉到财务/行业 |

## 六、面试表达要点

### 30 秒电梯陈述

> 我做了一个对公信贷尽调智能体，输入企业名，7 分钟生成一份 8 章授信报告，200 条证据可追溯。核心解决三个问题：报告从手写 2-5 天压缩到分钟级、AI 报告从黑盒变成可审计、报告深度从"堆数字"提升到"有归因有对标"。6 家上市公司实测全部通过质量门，90 分以上。

### 被追问技术时的分层回答

| 层级 | 怎么讲 |
|---|---|
| **第一层（业务效果）** | 7 分钟、200 条证据、90 分、6 家公司 0 错分 |
| **第二层（怎么做到的）** | Plan-Execute 研究引擎 + 4 专项 Agent + 规则引擎做计算 + LLM 做诊断表达 |
| **第三层（技术细节，被追问才讲）** | LangGraph 状态机、Evidence Store、CodeAct 确定性工具、混合检索 + 重排、二轮补证多跳 |

### 差异化（对比 Dify/百融方案）

| | Dify/百融 | 本系统 |
|---|---|---|
| 交付形态 | 端到端应用 | API/SDK 原子化能力 |
| 可审计性 | 弱（黑盒文本） | 强（Claim-Evidence 绑定） |
| 财务深度 | LLM 凭空分析 | 规则引擎计算 + LLM 诊断表达 |
| 行业识别 | 依赖 LLM | 规则+LLM 裁判+主营校验 |
| 状态机 | 弱 | LangGraph 原生 interrupt/resume |

## 七、已知待改进（诚实面对）

| 待改进项 | 当前状态 | 影响 |
