# 尽调智能体平台 — 业务设计文档

> 本文档定义业务流程、指标语义、页面目标，是 UI 设计的唯一上游依据。

---

## 一、任务状态机

### 核心实体：尽调任务（DueDiligenceTask）

一笔尽调任务 = 银行对某个企业的一次信用风险评估作业。

### 状态定义

```
created → gathering → analyzing → report_ready → under_review → approved / rejected
                                                              ↘ archived
```

| 状态 | 含义 | 谁在操作 | 停留时长 |
|------|------|----------|----------|
| `created` | 任务刚创建，尚未开始 | 系统自动创建（触发条件见下） | < 1 天 |
| `gathering` | AI 正在采集和解析数据 | 系统自动，人工辅助上传 | 2-4 小时 |
| `analyzing` | AI 正在生成风险分析 | 系统自动 | 10-30 分钟 |
| `report_ready` | 报告已生成，等待人工复核 | 客户经理 | 1-3 天 |
| `under_review` | 已提交审批，审批人审阅中 | 审批人 | 1-5 天 |
| `approved` | 审批通过 | — | 永久 |
| `rejected` | 审批驳回 | — | 永久 |
| `archived` | 归档（超过 90 天或手动归档） | 系统/人工 | 永久 |

### 状态流转条件

```
created
  └─ [触发条件满足] → gathering
       企业数据接口就绪 OR 人工上传资料包

gathering
  └─ [数据采集完成 + 解析完成] → analyzing
       所有数据源返回结果，文档解析进度 100%

analyzing
  └─ [风险分析完成] → report_ready
       AI 生成完整报告（含评分、风险项、建议）

report_ready
  ├─ [客户经理确认并提交] → under_review
  └─ [客户经理要求重新生成] → analyzing  （回退）

under_review
  ├─ [审批人通过] → approved
  ├─ [审批人驳回] → rejected
  └─ [审批人退回修改] → report_ready  （回退）

approved / rejected
  └─ [超过 90 天] → archived  （自动）
```

### 触发创建的业务场景

| 场景 | 触发方 | 任务类型 |
|------|--------|----------|
| 新客户首次申请授信 | 客户经理手动创建 | `first_credit` |
| 存量客户年度复审 | 系统自动创建（到期前 30 天） | `annual_review` |
| 贷后预警触发 | 系统自动创建（风险指标超阈值） | `post_loan_warning` |

### 关键规则

1. **gathering 和 analyzing 是自动态** — 人工不介入，只监控进度
2. **report_ready 是唯一的人工工作态** — 客户经理在这里花最多时间
3. **under_review 可以回退到 report_ready** — 审批人发现报告质量问题时
4. **rejected 不是终点** — 可以补充材料后重新走 gathering → analyzing → report_ready

## 二、核心指标语义

### 指标 1：数据引擎健康度

| 维度 | 定义 |
|------|------|
| **是什么** | 已连接数据源数 / 总数据源数 × 100% |
| **谁看** | 系统管理员、客户经理 |
| **用来做什么** | 判断当前 AI 分析结果的**数据完整性**。健康度 < 60% 时，AI 报告应标注"数据不完整，结论可信度降低" |
| **当前值含义** | 4/5 = 80%，税务数据正在同步，不影响工商/征信/流水/司法的核心分析 |
| **行动指引** | 健康度 100% → 可以放心启动任务；< 80% → 检查异常数据源；< 60% → 暂停新任务创建 |

### 指标 2：自动化率

| 维度 | 定义 |
|------|------|
| **是什么** | AI 自动完成的报告页数 / 总报告页数 × 100% |
| **谁看** | 部门主管、运营 |
| **用来做什么** | 衡量 AI 对人工的**替代程度**。自动化率越高 = 人工复核时间越短 = 任务周转越快 |
| **当前值含义** | 82.5% = 每 100 页报告中，82.5 页由 AI 生成，17.5 页需要人工补充（通常是行业特殊判断、关联交易分析等） |
| **行动指引** | > 80% → AI 能力成熟；60-80% → 优化 prompt/模板；< 60% → 检查数据源或模型问题 |

### 指标 3：风险等级

| 维度 | 定义 |
|------|------|
| **是什么** | AI 基于多维数据综合评定的企业信用风险等级 |
| **谁看** | 客户经理（日常）、审批人（决策） |
| **用来做什么** | **审批决策的核心输入**。高风险 = 需要更多抵押/担保/更高利率；低风险 = 可以简化流程 |
| **评定依据** | 财务指标（40%）+ 行业环境（20%）+ 司法信息（15%）+ 舆情（10%）+ 管理层评估（15%） |
| **等级含义** | 低风险 → 建议通过；中风险 → 有条件通过；高风险 → 建议拒绝或大幅增加风控措施；极高风险 → 直接拒绝 |

**风险等级不是静态的** — 一笔任务在 `analyzing` 阶段评定风险等级，在 `report_ready` 阶段客户经理可以复核调整（需要写理由）。

## 三、首页定位

### 结论：首页是"任务分发台"，不是"数据总览台"

**理由：**

1. **用户画像** — 核心用户是客户经理（张经理），他每天打开平台的目的是"看看今天有什么要处理的"，不是"看看全局指标"。全局指标是部门主管看的，频率低（周报/月报级别）。

2. **操作频率** — 任务操作是**每天**，指标查看是**每周/每月**。高频操作应该占据首页核心位置。

3. **决策路径** — 客户经理的决策链是：
   ```
   打开首页 → 找到优先任务 → 点击开始 → 进入数据整合/分析/报告
   ```
   不是：
   ```
   打开首页 → 看指标 → 做决策
   ```

### 首页结构（单一目标：让张经理 3 秒内找到今天要做的事）

```
┌─────────────────────────────────────────────────────┐
│ 首页 = 任务分发台                                      │
│                                                       │
│ ┌─ 核心区域（70% 视觉权重）────────────────────────┐ │
│ │                                                    │ │
│ │  任务列表                                          │ │
│ │  按紧急程度排序：                                   │ │
│ │  1. 贷后预警触发的任务（紧急，红色标记）              │ │
│ │  2. 即将到期的年审任务（3天内，橙色标记）            │ │
│ │  3. 正在进行中的任务（蓝色标记）                     │ │
│ │  4. 待开始的新任务（灰色标记）                       │ │
│ │  5. 已完成/已归档（折叠，默认隐藏）                  │ │
│ │                                                    │ │
│ │  每条任务：企业名 + 状态 + 风险等级 + 一个主操作按钮  │ │
│ │                                                    │ │
│ └────────────────────────────────────────────────────┘ │
│                                                       │
│ ┌─ 辅助区域（30% 视觉权重）────────────────────────┐ │
│ │                                                    │ │
│ │  AI 摘要卡片（一句话）：                             │ │
│ │  "今日 3 个任务待处理，其中 1 个为高优先级预警"       │ │
│ │                                                    │ │
│ │  快捷入口：                                         │ │
│ │  [新建任务] [查看月报] [数据引擎状态]               │ │
│ │                                                    │ │
│ └────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

### AI 看板应该放在哪？

**不应该放在首页。** AI 看板（指标、图表、健康度）是**部门主管视角**，属于独立的"运营监控"页面，不是客户经理的日常工作入口。

如果面试中需要展示 AI 看板能力，可以放在一个独立的 `/analytics` 路由下，或者作为 Dashboard 的二级 tab（"我的任务" / "团队概览"）。

## 四、对当前 UI 的直接影响

基于以上分析，当前 UI 需要做的调整：

| 当前状态 | 问题 | 应改为 |
|----------|------|--------|
| 首页同时有 AI 看板 + 指标 + 任务列表 | 三个目标打架 | 首页只保留任务列表 + AI 一句话摘要 |
| 4 个指标卡片占据大量首屏空间 | 客户经理不关心这些 | 移到独立的"运营分析"页面 |
| 数据引擎状态显示在首页 AI 卡片里 | 客户经理不关心数据源 | 移到系统设置或运营页面 |
| 任务状态只有 pending/in_progress/completed | 3 个状态无法表达业务流转 | 扩展为 7 个状态（见状态机） |
| "开始尽调"是唯一操作 | 缺少"复核报告"、"提交审批"等关键操作 | 根据任务状态显示不同主操作 |
| 风险等级只是标签 | 没有说明评定依据和决策含义 | 增加风险等级的评定依据说明 |

## 五、建议的下一步

1. **确认状态机** — 上述 7 个状态是否覆盖你的业务场景？是否需要增减？
2. **确认指标语义** — 三个指标的定义是否符合你理解的业务逻辑？
3. **确认首页定位** — 是否同意"任务分发台"的定位？如果需要保留指标，以什么形式保留？
4. **基于确认后的设计重构 UI** — 先画线框图，再上代码
