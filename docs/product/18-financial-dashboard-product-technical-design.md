# 18 财务驾驶舱与专业报告差距补齐设计

## 1. 对标结论

本轮参考外部 Agent 生成的上市公司贷前尽调报告后，确认当前 DDG-Agent 的主要差距不在于是否能生成自然语言，而在于报告装配层还不够像银行客户经理可直接使用的工作底稿。

对方报告体现出几个值得吸收的能力：

- 开篇给出资料完整度总览，而不是直接进入正文。
- 财务章节同时提供近三年核心表格、趋势分析和异常解释。
- 行业章节能写出细分赛道、周期位置、竞争对标和政策影响。
- 司法与工商章节使用权威/准权威来源形成可复核结论。
- 信贷建议章节包含准入意见、额度、期限、定价、提款条件和贷后监控。
- 附录保留数据来源、核心财务数据和调查过程说明。

本项目已经具备 DeepResearch 计划、Evidence Store、RAG、CodeAct 财务计算、质量评测和正文级引用基础，因此下一步应优先把这些能力组装成更稳定的报告体例。

## 2. 本轮 MVP 范围

本轮先补“财务驾驶舱”，让财务章节从文字和表格升级为可视化、可追溯、可诊断的三年趋势分析。

做法：

- 后端输出结构化 `financial_dashboard`，不生成图片。
- 前端用 ECharts 渲染九宫格图表。
- 每个图表包含诊断文本和 `evidence_refs`。
- 图表数据来自已解析三大表和内部财务计算工具，不使用 mock 数字。
- 数据不足时保留图表缺口说明，不硬编数据。

本轮不做：

- 不接入 iFinD、Wind、天眼查等商业数据终端。
- 不把 matplotlib 图片直接塞进报告。
- 不在客户侧暴露内部工具真实名称。
- 不替代后续行业、工商、司法章节的专项增强。

## 3. 九宫格图表定义

| 图表 | 目的 | 指标 |
| --- | --- | --- |
| 收入与净利润趋势 | 判断规模增长是否转化为利润 | 营业收入、净利润 |
| 毛利率与净利率趋势 | 判断盈利能力和费用消化能力 | 毛利率、销售净利率 |
| 杠杆水平趋势 | 判断资产负债安全边际 | 资产负债率、参考线 |
| 短期偿债能力 | 判断流动性缓冲 | 流动比率、速动比率、参考线 |
| 现金流结构 | 判断经营造血和投资融资依赖 | 经营、投资、筹资现金流 |
| 资产结构 | 判断资产沉淀和重资产程度 | 货币资金、应收账款、存货、固定资产、在建工程 |
| 营运资金占用 | 判断回款和库存压力 | 应收账款、存货 |
| 有息/经营性负债观察 | 判断短债压力和供应链占用 | 短期借款、应付票据、应付账款 |
| ROE 与 ROA | 判断资本回报能力 | ROE、ROA |

## 4. 数据结构

后端输出：

```json
{
  "financial_dashboard": {
    "title": "近三年财务指标驾驶舱",
    "years": ["2022", "2023", "2024"],
    "data_boundary": "图表基于已解析三大表生成，缺失科目以 null 表示。",
    "charts": [
      {
        "id": "revenue_profit_trend",
        "title": "收入与净利润趋势",
        "chart_type": "bar_line",
        "years": ["2022", "2023", "2024"],
        "unit": "元",
        "series": [{"name": "营业收入", "data": [1, 2, 3], "unit": "元"}],
        "threshold_lines": [],
        "diagnosis": "营业收入持续增长，但净利润改善幅度弱于收入。",
        "evidence_refs": ["ev_codeact_xxx"]
      }
    ]
  }
}
```

字段约束：

- `series.data` 使用数字或 `null`，前端负责格式化。
- `threshold_lines` 仅作为参考线，不作为硬性授信准入规则。
- `diagnosis` 必须是图表级诊断，不重复表格标题。
- `evidence_refs` 优先绑定内部财务计算和三大表校验证据。

## 5. 参考线策略

MVP 使用通用参考线，并在界面中标注为“参考线”：

- 资产负债率：70%。
- 流动比率：1.5。
- 速动比率：1.0。

后续应根据行业知识库注入行业阈值，例如半导体制造、地产、贸易、养殖和医药服务的杠杆与周转指标不可使用同一阈值。

## 6. 前端呈现

报告页新增财务驾驶舱模块：

- 完整尽调报告：显示在“财务状况与偿债能力”章节正文前。
- 单财务报告：显示在财务报告说明和详细表格之间。
- 每个图表卡片展示图表、诊断、证据来源摘要。
- 桌面端三列九宫格，窄屏降为两列或单列。

前端展示名称统一业务化：

- `codeact_financial_metric` 展示为“财务指标计算”。
- `codeact_financial_validation` 展示为“三大表勾稽校验”。
- 不展示内部实现、脚本名或供应商工具链。

## 7. 数据源缺口

Kimi 报告中部分内容依赖商业数据源或专有数据源。当前项目若要达到同等质量，需要补齐以下数据通道：

| 能力 | 当前状态 | 需要补齐的数据源 |
| --- | --- | --- |
| 工商股权、对外投资、历史处罚 | 搜索和公开资料兜底 | 客户自购工商 API、天眼查/企查查类授权、国家企业信用信息公示系统可用通道 |
| 高质量财务数据和行业中位数 | 上市公司公开资料 + 三大表解析 | 巨潮/交易所公告结构化解析、Wind/iFinD/Choice 或客户数据仓库 |
| 司法案件和执行信息 | 搜索兜底 | 裁判文书、执行信息、失信、行政处罚授权接口或客户内部数据包 |
| 行业市占率、竞争对标 | RAG + 搜索 | 研报 API、行业协会数据、客户采购数据库 |
| 授信限额和定价规则 | 通用规则 | 银行内部评级模型、额度测算规则、定价政策、担保准入规则 |

私有化部署时，建议由客户将上述商业/内部数据 T+1 推送到前置机，Agent 通过 MCP/Tool 拉取并生成 Evidence，而不是在内网中实时访问外网搜索服务。

## 8. 验收标准

本轮完成后应满足：

- 财务报告 JSON 包含 `financial_dashboard`。
- 当近三年数据充足时，`financial_dashboard.charts.length >= 6`，目标为 9。
- 图表不使用 mock 数字，不把格式化字符串作为数值传给前端。
- 每个图表至少包含一条诊断文本。
- 完整尽调报告和单财务报告均能展示财务驾驶舱。
- 前端构建通过，后端单测通过。
