# 非零售客户内部评级模型与验证体系参考

## 适用场景

用于授信报告中的客户评级、风险分层、额度建议和模型边界说明。本资料为监管和同业公开资料整理，不包含任何银行内部模型参数或代码。

## 监管框架

信用风险内部评级体系通常要求覆盖：

- 主权暴露。
- 金融机构暴露。
- 公司暴露，也称非零售客户。
- 零售暴露。

评级体系通常分为两类：

- 客户评级：主要估计违约概率 PD。
- 债项评级：关注 LGD、EAD、M 等债项维度参数。

## 模型方法

内部评级可以采用：

- 统计模型方法。
- 专家判断方法。
- 统计模型与专家判断结合。

无论采用哪种方法，都需要证明评级能准确反映客户风险，并且有清晰的治理、文档和验证机制。

## 模型治理要求

内部评级体系通常需要三类机制：

- 模型开发：定义样本、变量、方法、假设和参数。
- 模型验证：独立验证模型区分能力、稳定性和校准效果。
- 模型使用：将评级结果应用于授信准入、额度、定价、贷后监控和资本计量。

## 验证制度参考

同业公开项目资料中，内部评级验证制度通常覆盖：

- 验证目标。
- 验证原则。
- 验证范围。
- 验证方法。
- 验证流程。
- 治理架构和职责。

验证阶段：

- 投产前验证。
- 定期持续监控。
- 投产后验证。

## 验证对象

模型本体验证：

- 关键定义。
- 开发样本数据。
- 模型方法。
- 重要假设和参数。
- 开发过程。
- 结果应用。

支持体系验证：

- 使用政策和流程。
- 数据和信息系统。
- 应用情况和用户反馈。
- 文档记录完整性。

## 监控报告模板要素

同业内部评级监控报告通常包括：

- 模型区分能力指标，如 KS、AR。
- 评级迁徙矩阵。
- 评级分布统计。
- 违约率回溯。
- 行业、区域、评级等级维度信用风险暴露分布。
- 内部评级运行情况报告，提交董事会和高管层。

## 在当前项目中的使用边界

在未接入真实内部评级模型前，系统只能输出“风险评分”或“预评级参考”，不得宣称为本行正式内部评级。

可用表达：

> 当前评分为尽调 Agent 基于公开资料、专项报告和证据链形成的预评级参考，不等同于本行内部评级结果。正式评级应以本行内部评级模型、客户财务数据、征信和审批流程为准。

## 需人工复核事项

- 本行是否有正式内部评级模型及适用客群。
- 评级结果是否由有权系统生成。
- 财务数据、征信数据、行业分类是否满足模型输入要求。
- 评级是否已完成审批或复核流程。
